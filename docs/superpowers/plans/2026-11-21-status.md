# Jobsmith: status of the seven 2026-11-01 specs and their plans

Date: 2026-11-21. Branch: `docs/plans-2026-11-21` (local only, not pushed). Planning only: no product code was written or changed.

## TL;DR

- 7 of 7 specs covered. None of the seven is built, not even in part. All seven now have a plan: 361 tasks across 31 milestones (6 to 36).
- No spec was held back for a decision. Twelve questions for the owner are listed below; the plans run on the specs' own "assumed until the owner says otherwise" lists and on choices each plan names in one constant, so an answer changes a constant or a task, not a whole plan.
- The specs set a strict order (Prep, Hosted, Feed, Apply and Research, Debrief, Bridge part two, Widen). Only Prep is fully buildable on today's code. Seven milestones can start on Core alone: 6, 21, 22 (after one task of 20), 29, most of 30, 33, and most of 35 and 36.
- Recommended first step: Prep milestone 6 (Questions), 14 tasks, no account or service needed.
- The plans were drafted by seven Sonnet subagents, one per spec, from a shared brief, and checked mechanically. They were not read line by line. See "Not checked".

## Questions for the owner

1. **Are the seven specs approved as written, including each section 11 list of assumptions?** They are marked "draft for owner review" and were never pushed. The plans treat every assumption as decided.
2. **Figma drafts.** Every spec says each milestone plan is preceded by Figma drafts. None exist. Build from the plans and replace the copy marked "proposed" later, or draw first?
3. **Do the real question banks and debriefs follow the grammars?** The Prep spec says existing packets work on day one, but the repo's fixtures `nwl-answers-full.md`, `nwl-hr-bank.md` and `nwl-call-card.md` have no `### N.` heading and parse to zero rows, and `nwl-debrief-round2.md` uses headings outside the Debrief grammar. The plans add new fixtures and pin the zero-row result. If the real files look like the old fixtures, the parsers need more rules before milestones 6 and 25.
4. **Does the paid hosted service go ahead, and with which billing provider?** Stripe with Stripe Tax, or a merchant of record (Paddle, Lemon Squeezy). The plan prices, credits and caps are placeholders in two files. Needs a Stripe account, a Resend account with a sending domain, a legal text review and a zero data retention confirmation before launch.
5. **Demo sign-in beside hosted mode.** The Hosted plan refuses to boot with `HOSTED=true` and `DEMO_MODE=true` together, because demo accounts skip verification and would reach metered calls. The alternative is a capped demo account.
6. **Two credit rules the spec leaves open.** May a Free-plan user spend carried bonus credits (the plan says yes)? Does a refunded run count toward the daily caps (the plan says no)?
7. **Clips made by the CLI on a server with TTS off.** The Prep plan plays them (one constant stands in for provider and model in the hash). The spec's section 5.3 reads the other way.
8. **Feed.** The spec gives the feed step 120 seconds, Hosted's tick route allows 60: raise the route limit or accept about 50 seconds? Do Remotive's and Remote OK's current terms allow this use, or is a preset dropped?
9. **Debrief recording notice.** The wording is "settled with the owner": one text for the app and a separate one for `jobsmith transcribe`. Can the debrief skill write the section 5.2 headings?
10. **Bridge part two.** Review the twelve MCP tool descriptions and the request instruction texts before milestone 30 and 31 are built. What public address does the Runners empty state link to?
11. **Widen, people and legal.** CLA (the spec's recommendation) or DCO, the licensee's legal name, a lawyer's review, a project email address on a domain the owner controls, one practitioner per new pack to review its copy, a second person to run the self-host guide, a second GitHub account for the CLA test, and the tags the owner cuts (`v0.9.0-rc.1`, `v0.9.0-rc.2`, `v1.0.0`).
12. **`DEMO_MODE` in the variable table.** The code reads it, the Widen spec's list of 60 variables omits it. Keep it (61 rows) or remove the demo before 1.0?

Smaller choices are listed in each plan's README under "Needs an account, a paid service, hosting or the owner's answer" and under its numbered decisions (Feed D1 to D29, Hosted D1 to D19).

## Not checked

- **No test was run.** The new worktree has no `node_modules`, installing was out of scope, and the main checkout sits on an older branch. The plans' commands and expected results are unexecuted.
- **The plans were not read in full.** Seven Sonnet subagents wrote them. The checks made here: task counts match each task list (361), no duplicate task numbers, every task has Files and Acceptance, no em dashes or exclamation marks in prose, a script over every "Modify" path, and a read of the Prep README plus one task each from Prep and Hosted. Two subagent claims were verified by hand (the fixtures in question 3). Their other claims about spec ambiguities were not.
- **Test steps are often named cases with the spec's values in comments, not finished test code.** An executor writes the assertions.
- **Cross-plan names.** The plans were written at the same time. Each takes shared names from the specs, and Feed, Debrief and Bridge part two say they read Hosted's contract, but nobody reconciled the seven finished contracts against each other. Each milestone's "Before starting" tells the executor to read the real exports first.
- **Later milestones are written against code that does not exist.** Only milestones 6, 21, 22, 29, 30, 33, 35 and 36 were planned against real files. Expect to revise a later milestone file when its dependencies land, which is also what the specs ask for ("one plan per milestone, written when the previous one is done").
- **Outside facts.** Next.js 16 docs, Better Auth option names, the MCP 2025-06-18 message shapes, Stripe, Resend, `unpdf`, `mammoth`, `@react-pdf/renderer`, `docx`, the AWS and Vercel Blob clients, the ATS, Remotive and Remote OK field names, Caddy and Kokoro-FastAPI details were not looked up. Each is a confirm step in its task. No package version was invented.
- **Hand arithmetic.** The Funnel fixture and seed numbers in milestone 29 were computed by hand and never run.
- **One read outside the repo.** The Feed writer quoted the Ashby listing query from the owner's own Design Career Ops Web prototype, the port source the spec names (Feed README, D11). Nothing was copied from any client repository.
- **Remote state.** Nothing was fetched or pushed. Open pull requests on GitHub were not looked at.
